The challenge, in their words

Use real data collected by the applicant (a phone is enough) to drive a robotic manipulator in a simple simulation environment such as LIBERO. Showcase knowledge of VLAs and/or world models. Submit a public GitHub repo with a README covering how to run it, example outputs, design choices, and what worked and what didn't.

They judge on: creativity (the collected data must play a role), policy performance in sim and/or world-model prediction quality, implementation simplicity, and clear results "without AI slop".

Timeline risk

The posting gives the deadline as Friday 9 October 2026, 23:59 BST. Today is 8 October, so about 1.5 days remain. The full plan (6 phases, 50–100 teleop episodes, two trained models) does not fit that window. We need to cut scope to a minimal end-to-end path before starting Phase 1.

What we did

  • Read PROJECT_PLAN.md and the challenge posting.
  • Created conda env humanoidschallenge with Python 3.10. LIBERO and robosuite 1.4 target 3.8–3.10, so 3.10 is the newest safe choice. No packages installed yet; each step installs what it needs.
  • Initialised git, set origin to git@github.com:mi-robotics/HumanoidsChallenge.git, pushed main.
  • Wrote CLAUDE.md with the working rules: one step at a time, no speculative code, a report and tracker update after every step.
  • Started a progress tracker and this step report, both kept as HTML under docs/ and published as pages.
